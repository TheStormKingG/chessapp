# Puzzles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the eight-line Puzzles stub with rated, themed, daily and fix-my-mistakes puzzle solving, backed by a curated CC0 Lichess pool shipped as per-band packs.

**Architecture:** A build-time pipeline curates the Lichess dump into fixed-width per-band packs under `public/data/puzzles/`, fetched at runtime and served by the CacheFirst `/data/` route that already exists. Four pure modules own the logic — rating, selection, the attempt reducer and the stream queue — and two screens render them, mirroring `LessonPlayer` and the lesson path. Attempts append to the existing event log and the puzzle rating is projected from it, never stored as an independently mutable value.

**Tech Stack:** TypeScript strict with `noUncheckedIndexedAccess`, React 19, Vite 8, Dexie 4, chess.js 1.4, Stockfish 19 lite-single in a Web Worker, Vitest, Playwright, Workbox via vite-plugin-pwa.

**Spec:** `docs/superpowers/specs/2026-09-19-puzzles-design.md`

## C. Standing constraints

These are not suggestions. Each is a defect this codebase has already paid for.

1. **`chess.js` is imported only in `src/rules/rules.ts`.** Puzzle code calls `rules.ts`. If a rules function is missing, add it there with its own test — do not import `chess.js` a second time.

2. **A verifier sends `ucinewgame` between positions.** Without it the content verifier was stably wrong across four green runs; reversing file order changed the answer. Determinism is not correctness.

3. **Completion banks on arrival at the result screen**, never from a dismiss button's `onClick`. Banking from one exit turns every other exit into silent loss.

4. **A component rendered once per item in a sequence needs a `key`.** `KeyMomentView` shipped without one and every moment after the first rendered already revealed, while every single-item unit test passed.

5. **`explain.ts` returns `null` rather than state an unverified fact.** That is correct and must not be weakened. But its only call site once supplied no facts at all, so the two commonest themes rendered silently. Supply the facts; test that a real miss yields real text.

6. **Never `git add -A`.** Never commit `.env.secrets` or `.env.local`. Never print a secret value.

7. **A verification command's exit status must be the command's own.** Do not pipe a suite through `tail` and read the pipeline's status — it reports the filter's success, not the suite's.

8. **`PREVIEW=1` now builds before it serves.** Do not reintroduce a path that serves a stale `dist-e2e`.

```ts
/**
 * The puzzle vocabulary. Every other puzzle module imports from here, so this
 * file has no imports of its own beyond the rules types and adds no behaviour.
 *
 * `RatingBand`, not `Band`: src/review/types.ts already owns `Band` for the
 * move-label bands of PRD Appendix C, which is an unrelated concept.
 */

/** A Lichess puzzle theme, restricted to the eight PRD Appendix B assigns to Sections 1 and 2. */
export type Theme =
  | 'backRankMate'
  | 'mateIn1'
  | 'smotheredMate'
  | 'mateIn2'
  | 'attackingF2F7'
  | 'skewer'
  | 'fork'
  | 'discoveredAttack';

/** The rating bands the packs are split into. Half-open: `[min, max)`. */
export type RatingBand = '600-900' | '900-1200' | '1200-1500';

/** Where an attempt came from. Load-bearing: themed practice must not move the rating. */
export type PuzzleSource = 'rated' | 'themed' | 'daily' | 'fix';

/**
 * One puzzle as shipped in a pack.
 *
 * `fen` is the position BEFORE the opponent's last move is replayed, matching
 * the Lichess dump's own convention: the first move of `solution` is the
 * opponent's, and the learner moves second. Getting this backwards silently
 * asks the learner to play the wrong side, and every position still looks
 * legal, so no verifier catches it. Task 4 asserts the side to move.
 */
export interface Puzzle {
  id: string;
  fen: string;
  /** UCI moves. `solution[0]` is the opponent's move; the learner plays `solution[1]`. */
  solution: string[];
  rating: number;
  themes: Theme[];
}

/** The learner's puzzle rating: a number and how certain we are of it (spec §1.3). */
export interface PuzzleRating {
  rating: number;
  /** 0 = no evidence, 1 = settled. Monotonically non-decreasing. */
  confidence: number;
}

/** One finished attempt, as the session reducer reports it. */
export interface AttemptResult {
  puzzleId: string;
  solved: boolean;
  hinted: boolean;
  misses: number;
  ms: number;
  source: PuzzleSource;
  /** PRD 6.4 mastery: no hint and no miss. */
  mastered: boolean;
  /** False for themed practice and for any solve after a hint (F-PZ-4). */
  ratingCounts: boolean;
}
```

```js
/**
 * Curate the CC0 Lichess puzzle dump into per-band packs (PRD 8.4, F-PZ-9).
 *
 * Input:  .cache/lichess-puzzles/lichess_db_puzzle.csv  (gitignored, ~250 MB)
 * Output: public/data/puzzles/<band>.txt                 (committed)
 *
 * The output is one fixed-width record per line, sorted by rating, so a
 * lookup is a binary search over the file rather than a parse of all of it —
 * the technique public/data/openings.txt already uses. Record layout:
 *
 *   <id:5><rating:4><themes:2><fen:><TAB><solution>
 *
 * is deliberately NOT what this does: a variable-length FEN makes fixed-width
 * impossible. Instead each line is padded to a constant LINE_WIDTH, so line N
 * starts at N * LINE_WIDTH and the binary search is arithmetic. A puzzle whose
 * record exceeds LINE_WIDTH is dropped and counted, never truncated — a
 * truncated FEN is still a parseable FEN, and would ship as a wrong position.
 */
import { createReadStream } from 'node:fs';
import { mkdir, writeFile } from 'node:fs/promises';
import { createInterface } from 'node:readline';
import { join } from 'node:path';

const CACHE = '.cache/lichess-puzzles/lichess_db_puzzle.csv';
const OUT_DIR = 'public/data/puzzles';

/** The eight themes PRD Appendix B assigns to Sections 1 and 2. */
const THEMES = ['backRankMate', 'mateIn1', 'smotheredMate', 'mateIn2',
                'attackingF2F7', 'skewer', 'fork', 'discoveredAttack'];

/** Half-open [min, max). Must match RatingBand in src/puzzles/types.ts. */
const BANDS = [
  { name: '600-900', min: 600, max: 900, target: 2700 },
  { name: '900-1200', min: 900, max: 1200, target: 2700 },
  { name: '1200-1500', min: 1200, max: 1500, target: 2600 },
];

const MIN_PLAYS = 50;        // Appendix B's own settled-rating bar
const MAX_DEVIATION = 100;   // ditto
const LINE_WIDTH = 120;

function bandOf(rating) {
  return BANDS.find((b) => rating >= b.min && rating < b.max) ?? null;
}

async function main() {
  let header = null;
  const kept = new Map(BANDS.map((b) => [b.name, []]));
  const dropped = { theme: 0, unsettled: 0, band: 0, tooLong: 0, oversize: 0 };

  const rl = createInterface({ input: createReadStream(CACHE), crlfDelay: Infinity });
  for await (const line of rl) {
    if (!header) { header = line.split(','); continue; }
    const cols = line.split(',');
    const at = (name) => cols[header.indexOf(name)] ?? '';

    const themes = at('Themes').split(' ').filter((t) => THEMES.includes(t));
    if (themes.length === 0) { dropped.theme += 1; continue; }

    if (Number(at('NbPlays')) < MIN_PLAYS || Number(at('RatingDeviation')) > MAX_DEVIATION) {
      dropped.unsettled += 1; continue;
    }

    const rating = Number(at('Rating'));
    const band = bandOf(rating);
    if (!band) { dropped.band += 1; continue; }

    const solution = at('Moves').split(' ');
    // Solution length counts the learner's moves, so subtract the opponent's
    // opening move. Below 1000 a six-ply combination is mis-banded whatever
    // its rating says.
    if (band.min < 1000 && solution.length > 4) { dropped.tooLong += 1; continue; }

    const record = [at('PuzzleId'), rating, themes.join('|'), at('FEN'), solution.join(' ')].join('\t');
    if (record.length > LINE_WIDTH) { dropped.oversize += 1; continue; }
    kept.get(band.name).push({ rating, record });
  }

  await mkdir(OUT_DIR, { recursive: true });
  const summary = [];
  for (const band of BANDS) {
    const rows = kept.get(band.name)
      .sort((a, b) => a.rating - b.rating)
      .slice(0, band.target);
    const body = rows.map((r) => r.record.padEnd(LINE_WIDTH - 1) + '\n').join('');
    await writeFile(join(OUT_DIR, `${band.name}.txt`), body, 'utf8');
    summary.push({ band: band.name, puzzles: rows.length, bytes: body.length });
  }
  console.log(JSON.stringify({ summary, dropped, lineWidth: LINE_WIDTH }, null, 2));

  // A band that came out empty is a filter that is wrong, not a band with no
  // puzzles: 5 million rows cannot yield zero at these thresholds.
  for (const s of summary) {
    if (s.puzzles === 0) {
      console.error(`band ${s.band} is empty — the filter or the column mapping is wrong`);
      process.exit(1);
    }
  }
}

main().catch((e) => {
  if (e.code === 'ENOENT') {
    console.error(`missing ${CACHE}\n\nDownload the CC0 puzzle dump once:\n` +
      `  mkdir -p .cache/lichess-puzzles\n` +
      `  curl -L https://database.lichess.org/lichess_db_puzzle.csv.zst -o .cache/lichess-puzzles/puzzles.csv.zst\n` +
      `  zstd -d .cache/lichess-puzzles/puzzles.csv.zst -o ${CACHE}\n`);
    process.exit(1);
  }
  throw e;
});
```

```ts
import type { PuzzleRating } from './types';

/** F-PZ-1: start at 800 with high uncertainty. */
export const START: PuzzleRating = { rating: 800, confidence: 0 };

const MIN = 400;
const MAX = 3000;
/** The step at zero confidence. Large, so the first dozen attempts find the level fast. */
const MAX_STEP = 64;
/** The step at full confidence. Small, so a settled rating drifts rather than jumps. */
const MIN_STEP = 8;
/** How fast confidence accrues. 1/24 means roughly 24 attempts to be mostly settled. */
const CONFIDENCE_PER_ATTEMPT = 1 / 24;

/**
 * Expected score on the logistic curve, the same shape Elo and Glicko use.
 * 400 is the scale constant: a 400-point gap is about a 91 per cent expectation.
 */
function expected(rating: number, puzzleRating: number): number {
  return 1 / (1 + 10 ** ((puzzleRating - rating) / 400));
}

/**
 * One attempt's update.
 *
 * The surprise term `(actual - expected)` is what makes a hard solve worth more
 * than an easy one without a second rule: beating a 1200 from 800 has a large
 * surprise, beating a 600 has almost none.
 *
 * Pure and total. Swapping in Glicko-2 later replaces this function and nothing
 * else, because the persisted shape already carries a confidence.
 */
export function nextRating(
  current: PuzzleRating,
  puzzleRating: number,
  solved: boolean,
): PuzzleRating {
  const step = MAX_STEP - (MAX_STEP - MIN_STEP) * current.confidence;
  const surprise = (solved ? 1 : 0) - expected(current.rating, puzzleRating);
  const rating = Math.round(
    Math.min(MAX, Math.max(MIN, current.rating + step * surprise)),
  );
  const confidence = Math.min(1, current.confidence + CONFIDENCE_PER_ATTEMPT);
  return { rating, confidence };
}
```
